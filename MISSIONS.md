# Missions: maps, heights and scripts

A mission is **one XML file** in `crates/tactics_game/assets/missions/`. It
defines the grid (including where it is cut out), a height map, the units,
props and zones, and scripts attached to any of them.

```
assets/missions/
├── index.xml               lists the missions (and which one starts first)
├── training.mission.xml        Basic Training: guided controls tutorial
├── depot.mission.xml           small demo
├── rooftops.mission.xml        heights and ladders
├── proving_grounds.mission.xml 40x32 sandbox: every mechanic
├── holdout.mission.xml         defend a point, then extract
├── complex.mission.xml         explore and clear a facility
├── infiltration.mission.xml    sneak in, steal data, get out
└── lab.mission.xml             Character Lab (F7)
```

The four large levels are generated by `tools/gen_missions.py` (rooms,
walls and doors drawn with small helpers, positions checked). The output is
plain mission XML, so you can edit the files by hand too.

Files load through Bevy's asset server, so the same folder works on desktop,
web and Android. Errors (bad XML, unknown element, position outside the map,
script syntax errors) are shown in the combat log with **line and column**.
`cargo test -p tactics_game` parses every listed mission and plays each one
AI-vs-AI to catch broken content.

## Adding a mission

1. Copy `depot.mission.xml` to `my_level.mission.xml` and change its `id`.
2. Add it to `index.xml`: `<mission file="my_level.mission.xml"/>`
   (`<missions start="my_level">` makes it the one that starts first).
3. Run the game. Pick it from the **Missions** button in the HUD.

## Coordinates

`x` = column from the **left**, `y` = row from the **top**, exactly as you
read `<layout>`. (Scripts use the same convention.)

## The file

```xml
<mission id="ambush" name="Ambush" win="eliminate" seed="42">
  <description>Shown in the mission list.</description>

  <layout>
    ..........
    ..##...h..
    ..##...H..
  </layout>

  <heights>
    2200000000
    2200000000
    0000000000
  </heights>

  <!-- rectangle helpers, applied in order after layout/heights -->
  <cutout x="9" y="0" width="1" height="3"/>
  <raise x="4" y="0" width="2" height="1" level="1"/>
  <terrain x="5" y="2" type="half"/>
  <ladder x="2" y="2"/>

  <deploy team="player" squad="player" x="5" y="2"/>
  <unit team="enemy" class="sectoid" name="Leader" x="8" y="0" tag="leader">
    <script on="death">message("Leader down!");</script>
  </unit>
  <prop tag="barrel" kind="barrel" x="6" y="1" cover="half" hp="2">
    <script on="destroyed">explode(x, y, 1.5, 3);</script>
  </prop>
  <zone tag="exit" x="0" y="2" width="2" height="1">
    <script on="enter" team="player">win();</script>
  </zone>
  <tile x="7" y="2"><script on="enter" once="true">message("Click.");</script></tile>

  <script>fn shout(s) { message(s + "!") }</script>
  <script on="start">shout("Go");</script>
</mission>
```

### `<mission>` attributes

| attribute | meaning |
|---|---|
| `id` | unique id (used by `index.xml` `start` and the `mission:<id>` UI command) |
| `name` | display name |
| `win` | `eliminate` (default): killing every enemy wins. `script`: only `win()` wins. Losing the whole squad always loses. |
| `seed` | fixed random seed (same dice every time); omit for random |
| `width`, `height` | optional; taken from `<layout>` otherwise |
| `fog` | `true`: the player only sees enemies their squad can see |
| `concealment` | `true`: the squad starts concealed (see [Mission mechanics](#mission-mechanics)) |
| `detection` | tiles at which an unalerted enemy notices a concealed soldier (default 5) |

### The grid

| element | meaning |
|---|---|
| `<layout>` | one character per tile, first row = top. `.` floor, `#` **cut out** (no tile: impassable, not drawn), `h` half cover, `H` full cover. Any other character is floor. |
| `<heights>` | same shape as the layout: ground level `0`-`9` per tile. |
| `<surfaces>` | same shape: how each tile **looks** (rules ignore it). Ground: `c` concrete, `a` asphalt, `l` road markings, `g` grass, `d` dirt, `w` wooden floor, `r` roof, `m` metal. Cover/walls: `B` brick (a low brick tile is a window), `C` shipping container, `G` hedge, `T` tree, `R` rock, `S` sandbags, `F` fence. Cut-outs: `W` water. `.` = default. Without this layer the mission is styled automatically (concrete, roofs on raised ground, brick wall runs, containers, sandbags); `<mission style="none">` keeps the plain look. |
| `<cutout x y [width height]>` | cut a rectangle out of the grid. |
| `<raise x y [width height] level>` | set the ground level of a rectangle. |
| `<terrain x y [width height] type>` | `floor`, `half`, `full` or `void`. |
| `<ladder x y [width height]>` | ladder/ramp tiles (see below). |

### Height rules

* A unit can step **up at most 1 level** per step. Its class's `climb` stat
  can raise this (the Drone Pack's drones have `climb: 9`, so they fly).
* **Ladders** allow any climb into or out of their tile.
* Stepping **down** is always allowed. Climbing costs +1 movement point per
  level.
* **Line of sight** is 3D: sight lines run between units' eyes (1.5 levels
  above their ground). A 1-level step doesn't block sight; a 2-level cliff
  does; high ground sees over walls.
* **Cover from terrain:** a neighbouring tile 1 level higher is half cover,
  2+ levels is full cover.
* **High ground:** +15 aim when firing from higher ground
  (`CombatRules::height_advantage_bonus`).

### Contents

| element | attributes |
|---|---|
| `<deploy>` | `team`, `squad` (a squad id from the modules, e.g. `player`), `x`, `y`: places the squad around that tile |
| `<unit>` | `team` (`player`/`enemy`), `class` (from the modules), `name`, `x`, `y`, `tag` (for scripts), `dormant="true"`, `pod`, `patrol="x,y x,y ..."` (see below), `loadout` (preset id), `weapon`, `armor`, `items="frag scope"` (see MODULES.md, Loadouts) |
| `<door>` | `tag`, `x`, `y`, `width`, `height`, `locked="true"`: door panels; may hold `opened` scripts |
| `<prop>` | `tag`, `kind` (`crate`, `barrel`, `console`... used for visuals), `x`, `y`, `cover` (`none`/`half`/`full`; any cover blocks movement), `hp` (omit = indestructible), `model` |
| `<zone>` | `tag`, `x`, `y`, `width`, `height`: an area for `enter` scripts. Optional `marker` (`evac`, `objective`, `danger`, or `none`), `label`, `hidden="true"` (see below) |
| `<tile>` | `x`, `y`: a 1×1 zone (same optional attributes) |
| `<script>` | without `on`: shared functions for all scripts. With `on`: a hook (below). |
| `<sky>` | the background: `color="#88aacc"` (solid), `top="#2a5d9a" horizon="#e8c49a"` (vertical gradient), or `image="skies/dusk.png"` (a panorama, see below) with optional `rotation="90"` (degrees). Colours are `#rgb` or `#rrggbb`. No `<sky>`: the default dark sky. |

Area attacks (grenades, `explode`) damage destructible props and **walls**;
a destroyed prop frees its tile. Terrain cover has hit points: walls 6
(containers and metal 10), low cover 3, low rocks 8; tall rocks can't be
broken. A broken high wall collapses into **rubble** (half cover, 3 HP, map
character `u`); broken low cover becomes open ground. Grenades also throw
**shrapnel**: fragments that fly past the blast and hit whoever is in their
path (walls stop them). Prop kinds with their own look: `barrel`, `crate`,
`console`/`terminal`, `beacon`/`uplink` (anything else is a crate or wall).

**Supply caches** are props with `cover="none"` and kind `supply_ammo`
(+1 magazine and a full clip), `supply_medkit` (+4 HP) or `supply_grenade`
(+1 grenade, or a magazine for soldiers without one). A soldier who steps on
one takes it (`SupplyFound` event); they glow in the level and show as gold
dots on the minimap.

### Skies

```xml
<sky color="#2b3138"/>                              <!-- solid colour -->
<sky top="#3b6aa8" horizon="#e9dcc0"/>              <!-- gradient: overhead, horizon -->
<sky image="skies/dusk.png" rotation="200"/>        <!-- panorama image -->
```

An image sky is an **equirectangular panorama** (2:1, like a 360° photo:
left to right goes once around, top is straight up, the middle row is the
horizon) wrapped around the battlefield. Put it under `assets/skies/`
(PNG or JPG); `rotation` turns it to place the sun. Colours given with an
image show while it loads. The game ships `skies/dusk.png`. Generated
missions get a gradient that suits their theme.

## Generated missions

The **Missions** panel can generate a mission (`generate:<theme>` UI command,
`TBS_MISSION=gen:urban` on desktop; the old "skirmish" now generates one too).
`tactics_core::levelgen::generate` builds an ordinary `MissionDef`, so it
uses doors, props, marked zones, dormant pods, patrols and scripts like a
hand-made file. Same seed + settings = same mission; **Restart** replays it.

| theme | what you get |
|---|---|
| Urban | a street grid with lane markings; blocks with brick buildings (windows, doors, wooden floors, furniture), flat roofs with parapets and ladders, plazas with trees and hedges; parked cars, barrels, crates |
| Industrial | an asphalt yard with concrete pads, warehouses, rows of coloured shipping containers (some stacked with ladders), fences, fuel-barrel clusters |
| Wilds | grassland with stepped hills, a winding river with bridges, a dirt track, woods, rocks, hedgerows and a cabin |
| **Outbreak** | a **500x500** zombie city (`gen:outbreak`, the *Outbreak* button): a full street grid; blocks of shops, **multi-storey towers** (a walled ground floor and up to three upper floors, each set back from the one below, joined by flights of stairs, with parapets), **split-level car parks** (decks 1.5 m apart joined by ramps), flat roofs with ladders and parks with ponds; wrecked cars and barricades; about 230 **supply caches** (more of them indoors and upstairs); about 350 **zombies** (2 HP each; they fall together in the background instead of one death sequence at a time) in dormant hordes of 3-10 (two packs awake from the start). Objective: get the squad to the EVAC far to the north. |

| objective | win | lose |
|---|---|---|
| Eliminate | kill every hostile | squad wiped out |
| Extract | every living soldier on the EVAC zone (north), or kill everything | squad wiped out |
| Hold | survive 6 turns; waves attack the BEACON | beacon integrity reaches 0 |
| Recover | grab the DATA, then every living soldier back on the EVAC point (south) | squad wiped out |

Outbreak is not in the random rotation (`any`). Its size is in
`GenParams::outbreak` (`width`/`height` work for any theme).

The squad deploys at the south edge; objectives and enemies are only placed
on tiles reachable from there (doors count as open, climbing obeys the 1-level
rule and ladders), so every result is playable. Tests generate every theme
and objective over several seeds and play them AI-vs-AI.

## Mission mechanics

Each mechanic is independent: switch it on with an attribute and drive it
from scripts. They live in `tactics_core/src/battle/stealth.rs` (rules) and
`ai.rs` (behaviour).

| mechanic | how it works | XML | scripts |
|---|---|---|---|
| **Dormant pods** | a dormant enemy holds position (it sits its turns out without taking actions). It wakes when the squad sees it or it sees the squad, when it is hurt, when the alarm sounds, when it **hears gunfire** (classes with `hearing`, e.g. zombies: 14 tiles), or by script. Units sharing a `pod` wake together. | `<unit dormant="true" pod="east">` | `wake(unit)`, `wake_all()`, `unit_dormant(unit)` |
| **Patrols** | a patrolling unit is dormant and walks its waypoints in a loop, one AP per turn, through doors. | `<unit patrol="10,4 10,20 3,20">` | |
| **Concealment** | unalerted enemies notice a soldier only within `detection` tiles **with line of sight** (red rings in the game). Being noticed or attacking raises the alarm: concealment ends, every enemy wakes, `alarm` hooks run. Without concealment there is no alarm unless a script raises it. | `<mission concealment="true" detection="4.5">` | `concealed()`, `alarm()`, `raise_alarm()`, `on="alarm"` |
| **Doors** | a closed door blocks movement and sight (full cover). Any unit stepping next to it opens it unless it's locked. Multi-tile doors open together. The AI paths through unlocked doors. | `<door tag="vault" x y width height locked="true">` | `open_door(tag)`, `close_door(tag)`, `lock_door(tag, bool)`, `on="opened"` on the door |
| **Fog of war** | enemies outside the squad's sight are hidden, their moves fast-forwarded; the HUD counts only hostiles in sight. The board is shaded: tiles in sight are clear, tiles seen before are dimmed, tiles never seen are dark (walls and cover too). | `<mission fog="true">` | |
| **AI goals** | while no enemy is in sight, a team's AI walks (by real path, through doors) towards its goal instead of hunting: attack a beacon, reach an evac pad. | | `ai_goal("enemy", x, y)`, `clear_ai_goal(team)` |
| **Objective** | text in the HUD's mission panel. | | `objective(text)` |
| **Area counts** | how many units of a team stand in a rectangle (whole squad at the evac pad? aliens on the beacon?). | | `count_in_area(x, y, w, h, team)` (`""` = any team) |

### Visible zones (evac pads, objectives)

Zones are invisible trigger areas unless they have a `marker`. Marked
zones glow on the floor, get a pulsing outline and a beam of light, and a
floating label:

```xml
<zone tag="evac" x="1" y="0" width="5" height="3" marker="evac" label="EVAC PAD (opens turn 7)">
<tile tag="console" x="32" y="16" marker="objective" label="SECURITY CONSOLE">
```

`evac` is green, `danger` red, anything else (`objective`) yellow. Zones
tagged `evac...`, `extract...` or `exit...` are marked `evac` automatically
(`marker="none"` turns that off). Scripts: `show_zone(tag, true/false)`
(e.g. hide a console once used, reveal an evac point late) and
`zone_label(tag, text)`.

Recipes from the bundled missions:

* **Defend, then extract** (`holdout`): `ai_goal("enemy", beacon)`; every
  enemy `turn_start`, `count_in_area` around the beacon lowers an
  `integrity` flag (`lose()` at 0) and a table of waves spawns attackers;
  on round 7 a flag opens the evac zone, whose `enter` script wins when
  `count_in_area(pad) == alive_count("player")`.
* **Clear a complex** (`complex`): `fog="true"`, rooms behind doors with a
  dormant pod each, a locked `core` door opened by a console tile, a
  `unit_killed` hook keeping the objective's count up to date.
* **Steal and escape** (`infiltration`): `concealment="true"`, patrols and
  dormant guards, a console that unlocks the vault, a terminal tile that
  sets `data`/`carrier` flags, an extraction zone that wins only for the
  carrier, and an `alarm` hook that opens the barracks, sends everyone to
  the extraction point and brings reinforcements every other turn.

## Scripts

Scripts are [Rhai](https://rhai.rs), a small Rust-like language, written
directly inside `<script>`. You can use `<`, `>` and `&&` freely: the loader
wraps script bodies in CDATA for you.

### Where they attach and when they run

| attached to | `on=` | runs when | `unit` is |
|---|---|---|---|
| `<mission>` | `start` | the battle begins | -1 |
| `<mission>` | `turn_start` | every turn start (`team` = whose turn) | -1 |
| `<mission>` | `unit_killed` | any unit dies | the dead unit |
| `<zone>` / `<tile>` | `enter` | a unit steps onto the area | the mover |
| `<unit>` | `death` | this unit dies | this unit |
| `<unit>` | `damaged` | this unit takes damage (`amount`) | this unit |
| `<unit>` | `spotted` | the player's squad first sees this unit | this unit |
| `<unit>` | `turn_start` | its own team's turn starts | this unit |
| `<mission>` | `alarm` | the alarm is raised (once) | the unit that noticed the squad, or -1 |
| `<door>` | `opened` | the door opens | -1 (`prop` = its tag) |
| `<prop>` | `damaged` / `destroyed` | the prop is hit / destroyed | -1 (`prop` = its tag) |

Options on `<script>`: `team="player|enemy"` (only for that team's units /
turns) and `once="true"` (run at most once).

Modules can also give a whole **class** scripts (`hooks` on a class, see
MODULES.md): every unit of the class carries them, in any mission. They
work exactly like `<unit>` scripts above.

### Variables

`round`, `team` (whose turn: `"player"`/`"enemy"`), `unit` (id or -1),
`prop` (tag or `""`), `x`, `y` (the event's tile), `amount` (damage taken).

### Functions

| function | effect |
|---|---|
| `message(text)` / `print(text)` | show a message |
| `spawn_unit(team, class, name, x, y)` | add a unit (nearest free tile) |
| `damage(unit, n)`, `heal(unit, n)`, `kill(unit)` | |
| `explode(x, y, radius, damage)` | blast hitting units and props |
| `damage_prop(tag, n)`, `destroy(tag)` | |
| `set_terrain(x, y, "floor"/"half"/"full"/"void")` | change a tile (e.g. open a door, collapse a floor) |
| `set_height(x, y, level)`, `set_ladder(x, y, true/false)` | reshape the level |
| `give_ap(unit, n)` | |
| `win()`, `lose()` | end the mission |
| `set_flag(name, n)`, `flag(name)` | mission variables (integers, default 0) |
| `unit_by_tag(tag)`, `unit_at(x, y)` | find units (-1 = none) |
| `unit_alive(id)`, `unit_hp(id)`, `unit_name(id)`, `unit_team(id)`, `unit_x(id)`, `unit_y(id)` | |
| `alive_count("player"/"enemy")`, `prop_alive(tag)`, `height(x, y)`, `terrain(x, y)` | |
| `count_in_area(x, y, w, h, team)` | units of `team` (`""` = all) in a rectangle (top-left corner x, y) |
| `zone_count(tag, team)` | living units of `team` (`""` = all) inside the zone `tag` (e.g. the whole squad on the evac pad: `zone_count("evac", "player") >= alive_count("player")`) |
| `objective(text)` | set the HUD objective |
| `fear(unit)`, `add_fear(unit, n)` | read / change a unit's fear (0-100; gains scaled by bravery, fearless units ignore it) |
| `raise_alarm()`, `alarm()`, `concealed()` | concealment / alarm |
| `wake(unit)`, `wake_all()`, `unit_dormant(unit)` | dormant pods |
| `open_door(tag)`, `close_door(tag)`, `lock_door(tag, locked)` | doors |
| `doors()`, `door_open(tag)`, `door_locked(tag)`, `door_x(tag)`, `door_y(tag)`, `door_distance(unit, tag)` | list the mission's door tags and read their state / position (first panel) / distance from a unit to the nearest panel |
| `ai_goal(team, x, y)`, `clear_ai_goal(team)` | where a team's AI heads when nobody is in sight |
| `show_zone(tag, on)`, `zone_label(tag, text)` | show/hide or relabel a marked zone |
| `unit_stat(unit, stat)`, `set_stat(unit, stat, n)`, `add_stat(unit, stat, n)` | read / change `"aim"`, `"defense"`, `"mobility"` (tiles per AP), `"sight"`, `"max_hp"` (permanent for the battle) |
| `unit_class(unit)`, `unit_max_hp(unit)` | |
| `units("player"/"enemy"/"any")` | array of living unit ids (loop with `for id in units("enemy") { ... }`) |
| `distance(a, b)` | tiles between two units |
| `chance(percent)`, `rand(lo, hi)` | random numbers from the battle's seed (deterministic: same battle, same rolls) |
| `say(unit, text)` | short callout floating over the unit (shown only if the squad can see it) |
| `stun(unit, turns)`, `unit_stunned(unit)` | knock a unit out: no action points (and no overwatch) for its team's next `turns` turns; `unit_stunned` = turns left |
| `set_name(unit, name)` | rename a unit |
| `mark_unit(unit, text)`, `unmark_unit(unit)` | a label that stays over the unit (e.g. a boss), shown when the squad can see it |

Example: a door that opens when a switch is used.

```xml
<layout>
  ....H....
  ....H....
</layout>
<tile x="0" y="1">
  <script on="enter" team="player" once="true">
    set_terrain(4, 1, "floor");
    message("The door slides open.");
  </script>
</tile>
```

### Safety and determinism

* Scripts can't touch the game directly: they read a snapshot and return
  commands that the rules engine applies, emitting normal events that the
  game animates. Same seed, same actions, same scripts: same battle (replays
  and multiplayer stay possible).
* Each run is capped (100,000 operations, call depth, string size), so an
  infinite loop just stops with an error. Scripts triggering scripts are
  cut off after 16 levels.
* Any error (syntax, unknown function, bad team name...) is shown in the
  combat log as `Script error: ...`; the battle continues.
* Script **functions** (`fn name(...)`) can't see trigger variables like
  `round` or `unit`: pass them as arguments. Modules can provide functions
  for every script with `script_library` (see MODULES.md).
* `Battle::dry_run_scripts()` runs every hook once without applying
  anything; the mission tests use it to catch typos in hooks a test game
  never reaches.
* Desktop: `TBS_MISSION=<id>` starts that mission instead of the index's
  `start` one.

### Extending the scripting API

1. Add a function in `register_api` (`tactics_core/src/script.rs`). Queries
   read the `ScriptWorld` snapshot; actions push a `ScriptCommand`.
2. For a new action, add the `ScriptCommand` variant and handle it in
   `Battle::apply_script_command` (`tactics_core/src/battle/world.rs`),
   emitting `GameEvent`s.
3. New hook events: add a `HookEvent` variant, parse it in
   `HookEvent::parse`, and call `fire(...)` where it happens in the rules.
